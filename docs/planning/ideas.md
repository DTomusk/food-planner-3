# Ideas

- Nutritional info on ingredients, backend can determine dietary factors (e.g. gf, vegan)
- Recipe variants with substitutions, potentially a branching family of recipes? Or we keep it sequential and a recipe version owns variants? 
- SSO: Google, MicroSoft etc.
- MFA: passwords alone aren't very secure, we should have a second factor (e.g. OTP) to secure user logins 
- User profile pictures 
- More info on recipe cards 
- User stats, e.g. reliability 
- Website stats, show which external food blogs etc. are popular 
- Unit conversion: allow mass to mass conversions and volume to volume (imperial/metric), store ingredient densities (even if approx.) to enable mass to volume and back
